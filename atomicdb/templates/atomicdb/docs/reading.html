The position page

Every number on a position page says where it came from. The small chip next to a value tells you whether an engine searched that position itself or the value was carried up from somewhere else.

What the chips mean

You seeIt means
a plain number, no chipThe position's own analysis: an engine searched this position itself, and that is what it reported.
backedThe value worked out from what the moves below already know (see Backed values). The chip shows how deep the chain is. Where the chip is a link, it jumps to the position the value comes from.
walkedThe same kind of value, carried up a line a visitor walked. No engine search supports it yet, and verification is queued automatically.
repetitionThe line repeats a position (see Repetition); details below.
a muted, italic number with a backed chipA number the position does not use yet (a floor): nobody has searched that move. Details below.
borrowedA number on a move row that another position's search wrote; details below.
The repetition chip, exactly
  • On a move row: the value of that move comes back to the position you are looking at, so the line repeats and the move is worth no more than 0, whatever its own page claims.
  • In the header: the chain that leads here returns to a position it has already been through.
  • On a disabled row: the move would re-enter the line you are playing. It counts as a draw (0), and when that draw is the best the side to move has, the board arrow points at it, marked repeat = draw.
  • returns on a move row: on this line, the move's own line comes back to a position already played, so the move is worth the best way out of that loop, not the number its own page shows. The move itself does not repeat: the chip names the moves after it that bring the line back (returns after …Bf8 Bh6 Be7, or just how many plies on a phone), and its tooltip names the way out the value comes from.
  • The values of the rows follow the line you came by. Where that makes the best row differ from the position's value above, the page says so under the table's heading.
Muted, italic numbers (floors)

A muted, italic number that still carries a backed chip is a floor the position does not take. Nothing has searched that move, only some replies to it are known, and its number would beat the lines the search of the position you are looking at published. It keeps its place in the table, the board arrow passes over it, and searching the move settles it.

The borrowed chip, exactly
  • On a move row, a number nothing has searched and no engine line of the position you are looking at gives. Another position's search wrote it, and the chip links there.
  • If no other position's lines give it (an older pass of this one may have), the link lands on the move's position, marked chain breaks here.
  • The header and the board arrow count only searched moves and the position's own analysis, so they can disagree with it until the move is searched.
  • A position with no search of its own shows no such chip: every number in its table comes from elsewhere, as its header already says.

The moves table

  • The line under the header says what the table below is made of: how many moves an engine searched itself, how many were seeded from an engine line running through this position, and how many are queued.
  • Moves sort by best known value from the mover's side, and by nothing else. A value from a 2B node search sits beside one from a 128M node search, and neither is hidden behind the other.
  • That is why a deeply analysed value can disagree with a shallow sibling row: the two numbers were bought with very different amounts of search, and the shallow one is the one likely to move. The gap is not papered over, it is queued.

The last column, depth, says how much search that is: the node budget of the deepest search the move's position has had (requests are 128M, 512M or 2B; older 10B searches and smaller automatic ones such as 32M show too), or a dash where no search has reached it yet.

  • Only a search that really ran counts: a request that was closed without one, because other work got there first, does not.
  • Hover the cell for the number of visits.

Each column

state

  • unsolved: the move's position is open, nothing is proven yet.
  • unexplored: open, and no engine has searched that position itself; any number it shows came from a line running through it.
  • WHITE_WIN, BLACK_WIN or DRAW: a proven result, followed by how it was proven: TERMINAL (the game is over on the board), MATE_PV (a mate line checked move by move), MINIMAX (from proven moves below it), TB (tablebase) or SOLVE (a full proof replayed on the server).
  • not in tree: a legal move nobody has stepped into yet. Following it adds it.

A small mark after the state says something is already on its way for that move, so there is no need to request it again:

  • queued analysis is requested and waiting for a worker.
  • running a worker is searching it right now.
  • writing the search has finished and its result is waiting to be written into the tree; the value updates once it is.
  • unconfirmed mate or unconfirmed win a worker reported a forced mate, or a line to a tablebase win, that the server could not prove, from an account whose unproven lines are not used. The move stays open until it is closed another way or the line is refuted.

The marks are as of when the page loaded: reload to refresh them.

eval

The value of each move for the side to move here, in centipawns (100 is about one pawn). Switch the eval to Pawns in the settings to see it in pawns from White's side instead (9500 becomes 95.00).

  • M3: a proven win for the side to move, mate in at most 3 moves, counting this move. -M3: a proven loss.
  • 10000: won, with no mate distance attached (-10000: lost). On an open move it is a value carried up from a move below that is already proven, before this position has closed.
  • 9501 to 9999: an engine announced a mate it has not proven: 10000 minus the number of moves to mate after this move, so 9997 is mate in 3 more moves. Negative numbers are the same for the other side.
  • 9250 to 9500: an engine found a tablebase win, not a mate count: 9500 minus the number of plies (half-moves) until its line reaches the tablebase position, so 9481 is a tablebase win 19 plies down and a shorter way in ranks higher. 9500 itself is a position already in the tables, or an older result whose distance was not kept. None of these is a mate distance.
  • 9000 to 9249: a very large engine eval that is neither a mate nor a tablebase win. Scores from 9000 up to about 15000 are squeezed into this range in order, so they always rank below any tablebase win.
  • up to 8999: a plain engine eval, as the engine printed it.
  • not analysed: no value yet. These rows sort just above proven losses, so a run of them can sit between the open moves and the proven losses at the bottom.

The coloured square at the start of each row is from the side to move here: proven win, proven loss, proven draw. Open moves are coloured by the size of their value, for either side: 500 or more, 200 to 499, less than 200 or no value.

The thin bar under a value splits it into win, draw and loss for the side to move here: green, blue and red, left to right. Hover it for the numbers.

  • A proven result (mate, tablebase, minimax, a finished game) and a move that repeats the line you came by (a draw) fill the bar with that one outcome.
  • Any other value gets an estimate from the score, drawn fainter: nothing in the tree stores a win/draw/loss, so the page turns the number into one with a simple logistic curve, win = 1 / (1 + e(400 − cp) / 150), loss the same for the other side, draw the rest. It is not calibrated on Atomic games: at 0 it reads 6 / 88 / 6, at +400 even odds of a win, at +1000 98 / 2 / 0. A move with no value has no bar.
  • With the eval switched to Pawns, the bar is turned to White's side too: its left end is White's.
  • Settings › Explorer columns › W/D/L bars hides or shows every bar; the choice is remembered in your browser.

pn / dn

Proof and disproof numbers of the active proof campaign: an estimate of how much work is left to prove the campaign's goal from that move (pn) or to refute it (dn). Smaller means closer, ∞ means it can no longer be done. They are not probabilities. Empty when the campaign has no estimate for that move.

depth

The node budget of the deepest search the move's position has had, or a dash if none has reached it yet; see the moves table above.

Playing a line, and keys

Under the board, Play best line walks forward from the position on screen, one position about every second, along the move the arrow shows. Play random line does the same with a move picked at random among those whose value is within 30 of the best. Each step is an ordinary page, so Back retraces the line. It only follows moves already in the tree, and stops on a proven or finished position, where there is no such move to follow, or after 40 plies. The button you pressed turns into Stop; Esc, Back or a click anywhere else stops it too.

On a computer the position page also takes keys, except while you are typing in a box: ← and → go back and forward, F turns the board round (for the rest of the visit in that tab), Q presses the Request button on a position that has one, and Esc stops a line in play.
