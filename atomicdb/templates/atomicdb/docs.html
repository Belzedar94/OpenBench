AtomicDB documentation

AtomicDB is a shared, growing database of analysed Atomic Chess positions. These pages explain where each number on the site comes from, and how you can help.

New here? Read Method for what closed (solved) means, then Reading a page to make sense of the explorer.

In short

  • Method: what makes a position closed, and how to contribute a worker.
  • A position row: the engine's own evaluation, the value worked out from the moves below it, and whether it is solved.
  • Backed values: a position takes the best value its analysed moves give it, and every such value ends in a real engine search.
  • Repetition: a line that comes back to where it has been counts as a draw, but only along the line you are playing.
  • The queue: one queue shared by account, so nobody can crowd everyone else out; your own worker serves your requests first.
  • Contributing: every analysis is credited to the account that delivered it.
  • API: query, request and manage your queue from a script.
  • Reading a page: what the chips next to the numbers mean.

Each page starts with a short summary and gives the exact rules further down.

Words used on these pages

TermMeaning
positionOne board situation, with the side to move. Stored once, however it was reached.
plyOne move by one side (a half-move).
nodesThe unit of engine search effort: roughly, positions the engine looked at. 128M = 128 million, 2B = 2 billion.
centipawns (cp)Engine scores; 100 is about one pawn. Given from the side to move unless a page says otherwise.
closed / solvedThe result of the position is proven by one of the four gates. Everything else is open (UNKNOWN).
point evalWhat one engine search reported about the position itself.
backed valueThe value worked out from the analysed moves below a position. See Backed values.
anchorThe real engine search a backed value ends in.
transpositionThe same position reached by a different move order. See Repetition.
request, workerA request asks for an analysis; a worker is a volunteer computer that runs it. See The queue.
ladder, rungAsking again buys a deeper search: 128M, then 512M, then 2B.
